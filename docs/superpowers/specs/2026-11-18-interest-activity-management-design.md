# 兴趣活动后台管理设计

## 目标

复用现有 `courses` 表，将小程序当前六项兴趣活动迁移为服务端数据，并提供仅平台管理员可用的查询、新增、编辑、显示/隐藏、排序和删除能力。小程序不再保留本地活动兜底，只展示接口实际下发的可见活动。

## 数据模型

沿用 `Course`：`id`、`title`、`category`、`cover_url`、`summary`、`suitable_grade`、`service_period`、`price_text`、`tags`、`content`、`sort_order`、`status` 和时间字段。`published` 表示小程序可见，`hidden` 表示隐藏。现有价格数值字段保留但管理页面不使用。

## 初始化

按稳定 ID 幂等补齐六项当前页面内容：编程与逻辑、英语口语、表达与阅读、练字、绘画、音乐与乐器。六张当前封面复制到服务端静态资源目录。已有同 ID 数据保留后台修改结果；历史“智习室/晚托”数据改为隐藏，保留已有业务关联。

## 管理后台

平台管理员菜单增加“兴趣活动”，网点负责人和老师无权访问。列表沿用现有查询、状态筛选和每页十条分页。表单支持封面上传、基本信息、标签、排序和显示状态。列表提供编辑、显示/隐藏和删除。若活动已被预约、报名或到店记录引用，删除请求返回业务提示，管理员可改为隐藏。

## 接口与小程序

`GET /api/public/courses` 和详情接口只返回 `published` 数据，封面地址转换为可直接访问的绝对 URL。小程序列表完全使用接口数据，按 `sort_order` 展示；接口失败显示加载失败，空列表显示暂无活动。点击活动进入服务端详情，再进入预约页面。

## 验证

覆盖初始化幂等、权限、状态过滤、删除保护、封面校验和绝对 URL；小程序覆盖不再使用本地兜底、隐藏后不展示、接口失败和详情跳转。最终运行两个工程的完整测试，并通过本地 4000 接口验证六项数据。
